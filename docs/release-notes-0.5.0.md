This release is a JIT preview: libjay now compiles the parts of a J program that an interpreter runs one item at a time, and every wheel ships two code generators for it. Cranelift compiles fast and is on by default; LLVM 21 is the optimising tier, linked statically into every wheel and C bundle. Answers are bit-identical to the interpreter by construction, and wherever a compiled loop meets a value it cannot vouch for (a NaN, an infinity, an index out of range, an integer near the edge of exact arithmetic) it hands the whole computation back to the interpreter, which answers exactly as before, errors included.

Three kinds of code compile. A fold's step: `] F.. v` and its relatives, the insert `v/` and the suffix scan `v/\.` with a train or an explicit step, so KAMA over a million bars went from 1608 ms to 61 and a CUSUM detector over five million rows runs in about 30 ms, against 238 for the best Polars spelling and 1.7 s in jconsole. A rank-0 body: `u"0` and `x u"0 y` where the body is arithmetic, tolerant comparison, an agenda `@.`, a power `^:n`, or an explicit definition with `if.`, `while.` and `for.`; a Mandelbrot escape count over a million points takes 61 ms with LLVM where the interpreter takes about 160 s, and the cells are split across the thread pool. A fused float map: with LLVM a fused chain of arithmetic becomes one vectorised loop, so a 12-term polynomial over five million floats runs 97 → 13 ms on one thread and 28 → 8.5 on the full pool.

The automatic policy compiles with Cranelift from about a thousand items and turns to LLVM for large work, because LLVM's compile costs 6–30 ms against Cranelift's 0.5. `LIBJAY_JIT` takes `0`, `auto`, `force`, `cranelift` or `llvm`, and `jay.jit_backends()` names the generators an installation has. Every JIT test and the whole J corpus run once per generator and are held to the interpreter bit for bit, and the two generators must compile the same set of steps.

Underneath, each float primitive's arithmetic now has one definition, in `src/scalar.rs`, which the interpreter, the fused kernels, the compiled code and the GPU shaders all share. Unifying them settled how `<.` and `>.` treat the two zeros: the base operand of the pass stands, as jconsole answers, and APL keeps the left operand, as GNU APL does. Two fused-kernel answers that had drifted from the unfused verb were fixed on the way.

Packaging changed with it. Every wheel is built on its own architecture and run before publishing, the macOS jobs moved off GitHub's retired `macos-14` image, and LLVM comes from our own static build of 21.1.8 per target, published as the `llvm-21.1.8-libjay-1` prerelease and checked by SHA-256. Wheels grow from about 8 MB to 23–33 MB, and they carry LLVM's licence as `LICENSE-LLVM`. Source builds stay hermetic: the sdist and `cargo add libjay` need no LLVM and compile with Cranelift alone, with a build warning saying how to add it, and a C program linking `libjay.a` now also links the C++ runtime.

The version number moves with the change: 0.5.0 is this release, and the dynamic-J milestone planned under that number ("J code that builds J code") becomes 0.6.0.
