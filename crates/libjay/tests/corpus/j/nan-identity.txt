// What a NaN counts as when values are compared for SAMENESS rather than
// for size. `nan` next door holds the arithmetic; this file holds the
// question of whether a NaN is a value at all, and the reference answers it
// three different ways depending on which family is asking.
//
// - The set verbs `~.`, `~:` and `-.` say a NaN is no value: two of them
//   are two items, and neither is the other.
// - `-:` says a NaN is the same value as a NaN and as nothing else.
// - The search family — `i.`, `i:`, `e.` and the `=` monad built on them —
//   compares by magnitude of difference, and no difference from a NaN is
//   ever large enough to separate the two, so a NaN is FOUND wherever it
//   looks and is found by whatever looks for it. Only where the comparison
//   is of one element: a longer cell is compared whole and matches
//   nothing. Inside a box the contents are compared whole, and there the
//   loose reading holds however long they are.
// - `/:` places a NaN after every number, so `\:` leads with it.
//
// A complex value with a NaN part is a value of its own throughout, never
// the same as another and never found.
//
// Where the reference contradicts itself the sentence is NOT here: its
// vectorised comparison answers `(2 $ _.) = (2 $ _.)` with `1 1` where its
// own scalar `_. = _.` is 0, and its `/:~` sorts to an order its own `/:`
// does not give. Those are tickets, not corpus lines.
