// Where libjay answers differently from GNU APL on purpose: each of these
// follows a documented choice of its own (Dyalog-style, or the rule its J
// frontend already uses) where GNU APL follows the ISO/APL2 one, or names a
// gap where GNU APL has an answer. The `? ` line says which.
//
// The snapshot records BOTH answers: the test holds libjay to its side, and
// `jay-corpus record` re-measures both and fails if a pair has quietly
// converged, which is the signal that the note (and the entry in
// docs/coverage.md) should go. The same list appears in docs/coverage.md.
// GNU APL refuses an arithmetic OVERFLOW under × ÷ and ⋆ and lets one
// through under + and *: `1E308×2` is DOMAIN ERROR there while
// `1E308+1E308` is ∞ and `*710` is ∞, and `2⋆1E10` is refused while
// `2⋆10000` — the same infinity by an integer exponent — is not. libjay
// refuses arithmetic with no VALUE (`÷0`, `⍟0`, `!¯3`, `0⋆¯1`, all of
// which GNU APL refuses too) and lets an overflow answer with the
// infinity it reached, in one rule for every operation. No published
// definition asks for the split, and matching it would mean refusing
// `1E308×2` while answering `1E308+1E308`.
1E308×2
? an overflow answers ∞ here, DOMAIN ERROR there
1E308×1E308
? an overflow answers ∞ here, DOMAIN ERROR there
2*1E10
? an overflow answers ∞ here, DOMAIN ERROR there
0×1E308+1E308
? an infinite operand multiplies here, DOMAIN ERROR there
(1E308+1E308)÷2
? an infinite operand divides here, DOMAIN ERROR there
// The gamma function underflows to zero far down the negative axis, and
// GNU APL prints that zero even at a POLE, where the value it stands for
// is undefined: `!¯1E20` is 0 there. libjay refuses it, as it refuses the
// nearer poles `!¯3` and `!¯1` that GNU APL refuses too.
!¯1E20
? a pole is refused here, an underflowed 0 there
// GNU APL truncates a rotate amount to a signed 32-bit integer before it
// reduces it modulo the axis, so a large one rotates by the wrong amount:
// the low 32 bits of 9223372036854775806 are ¯2, and ¯2 modulo 3 is 1.
// libjay reduces the amount the program wrote. Probed over sixteen
// magnitudes around 2⋆52, 2⋆53 and 2⋆63; the truncation explains all of
// them and nothing else does.
9223372036854775806⌽1 2 3
? the whole amount is reduced here, its low 32 bits there
// `∪` is nub over ITEMS here, so a matrix is legal; GNU APL restricts
// the monad to vectors.
∪2 3⍴1 2 3 1 2 3
? nub takes items of any rank here, vectors only there
// The circle functions on a REAL argument whose answer is imaginary: GNU
// APL carries a negative zero into the square root and lands on the lower
// branch, libjay takes the principal one, which is what J answers.
8○3
? principal branch here, the lower one there
¯8○3
? principal branch here, the lower one there
¯2○2
? principal branch here, the lower one there
// Ordering a complex number. GNU APL extends `< ≤ > ≥` to complex operands
// as a lexicographic order on (real, imaginary); libjay refuses, as the
// standard and J both do — a complex number has no order, only equality.
3J4<1J2
? no order on complex here, lexicographic there
0J1<1
? no order on complex here, lexicographic there
3J4≤3J4
? no order on complex here, lexicographic there
// Grading is a permutation, not a claim about size, so libjay grades a
// complex vector by (real, imaginary) — J's `/:` answers the same way.
// GNU APL refuses it.
⍋3J4 1J1
? complex grading here, a domain error there
// Complex equality. libjay compares the magnitude of the difference
// against ⎕CT, as the real comparison does; GNU APL's complex comparison
// is looser by about the square root of ⎕CT.
1J1=1.0000000001J1
? ⎕CT on the magnitude here, a much looser threshold there
// A sequence yields its last sentence and prints nothing on the way
// (CLAUDE.md); GNU APL prints the value of every statement.
1 2 3⋄4 5
? only the last sentence has a value here, every one prints there
// GNU APL's own bug, kept here so we notice if a later release fixes
// it: a scan whose axis has length 1 loses that axis, so a 2-by-1
// matrix scans to a 2-vector and a 1-element vector to a scalar. Every
// other axis length, and `⌽`/`⌿` on the same shapes, are fine there.
+\\2 1⍴⍳12
? scan keeps the shape here, drops a length-1 axis there
⍴+\\,5
? scan keeps the shape here, drops a length-1 axis there
// GNU APL spaces a nested display more widely than libjay does, which
// the whitespace-insensitive comparison above only sees through the
// length of `⍕`.
⍴⍕(1 2)(3 4)
? one space between items here, two there
// `⍺←v` inside a dfn is a DEFAULT here, as the published dfn model has it:
// a left argument that arrived keeps its value. GNU APL assigns
// unconditionally, so the default overwrites the argument.
F←{⍺←10 ⋄ ⍺+⍵} ⋄ 3 F 5
? ⍺← is a default here, an unconditional assignment there
// A block's value is its last sentence and nothing else is displayed —
// libjay's sequence rule, in a dfn as everywhere else. GNU APL prints the
// value of every statement that is not an assignment on its way through.
F←{⍵+1 ⋄ ⍵+2} ⋄ F 5
? only the last statement is displayed here, every one of them there
// A negative replication count is a run of fills. GNU APL takes one only
// as a SCALAR left argument and calls a vector holding one a length error,
// where APL2 and Dyalog spell out the general rule; libjay follows them.
¯1 2/1 2
? a negative count inside a vector is legal here, a length error there
1 ¯2/1 2
? a negative count inside a vector is legal here, a length error there
// Trains and function assignment: a Dyalog extension libjay ships on by
// default (`Dialect.trains`), so a run of functions is a function here and
// a SYNTAX ERROR in GNU APL, which has neither. Turning the setting off
// gives GNU APL's reading back. These lines pin the extension against the
// oracle: if a later GNU APL grows trains, the pair stops disagreeing and
// `record` says so.
(+/÷≢)1 2 3 4
? a train here, a SYNTAX ERROR there
(⌈/-⌊/)3 1 4 1 5
? a train here, a SYNTAX ERROR there
1 2(⊣,⊢)3 4
? a train here, a SYNTAX ERROR there
F←+/÷≢ ⋄ F 1 2 3 4
? a named tacit function here, a SYNTAX ERROR there
F←+/ ⋄ F 1 2 3
? a named derived function here, a SYNTAX ERROR there
// GNU APL extends `< ≤ > ≥` to characters, ordering them among themselves
// and before every number. libjay refuses, as the standard and J both do —
// a character has no magnitude, only identity — which is the same stance
// the complex rows above take.
'a'<'b'
? no order on characters here, the collating order there
'a'≤'b'
? no order on characters here, the collating order there
'a'<5
? no order between a character and a number here, one there
5<'a'
? no order between a character and a number here, one there
// A decode whose radix axis is EMPTY: every answer is the empty sum, which
// is zero, and GNU APL agrees about the SHAPE of the result — `⍴(⍳0)⊥2 3⍴⍳6`
// is 3 there — but raises DOMAIN ERROR when asked to print the value. Its
// own bug, kept here so a later release that fixes it is noticed.
(⍳0)⊥2 3⍴⍳6
? zeros here, a DOMAIN ERROR on display there
(2 0⍴0)⊥⍳0
? zeros here, a DOMAIN ERROR on display there
// An operator's left operand may itself be derived: `+/⍣0` is the reduction
// repeated no times. GNU APL binds the inner operator first — it reads
// `+(/⍣0)` and refuses — so every `f/⍣n` and `f/⍤r` parts company there.
// The fuzz generator parenthesises the operand for exactly this reason.
+/⍣0 ⍳3
? a derived left operand here, a SYNTAX ERROR there
⌈¨⍣2 ⍳3
? a derived left operand here, a SYNTAX ERROR there
+/⍤1⊢2 3⍴⍳6
? a derived left operand here, a SYNTAX ERROR there
// Monadic `⊣` is the identity here, as the Dyalog line has it and as the
// status table promises. GNU APL gives it no result at all: the sentence
// displays nothing and `⍴⊣1 2 3` is as blank as `⊣1 2 3` is.
⊣1 2 3
? identity here, no result at all there
⊣'abc'
? identity here, no result at all there
⊣2 3⍴⍳6
? identity here, no result at all there
// A named gap: matching two EMPTY nested arrays compares their prototypes
// in APL2, and libjay compares only shape and whether the type is
// character. `⍬≡0⍴⊂1` agrees; `⍬≡0⍴⊂⍬` is where the prototype would decide.
⍬≡0⍴⊂⍬
? prototypes of empty nested arrays are not compared here
// The same order of GNU APL's reaches ⍸ and the rest of the relational
// family: a boxed or character bound is placed among the numbers there and
// refused here. `=` and `≠` are defined across types and agree.
'a'≥'b'
? no order on characters here, the collating order there
'a'>5
? no order between a character and a number here, one there
1 2<'ab'
? no order between a character and a number here, one there
'a'⍸1 1
? no order between a character and a number here, one there
(⊂⍳3)⍸¯2 0 2
? no order between a nested value and a number here, one there
// Enlist of an empty: APL2 defines ∊ as the simple vector of the simple
// scalars of its argument, which for an empty argument is an empty vector.
// GNU APL answers a ONE-element vector holding a zero. Dyalog agrees with
// libjay.
⍴∊⍳0
? the empty here, one element there
∊0 3⍴0
? the empty here, one element there
// An integer near 2^63 is exact here and goes through a double in GNU APL,
// which rounds it to 2^63 before the verb sees it. libjay reads the literal
// out of its text and keeps it exact, so the residues and the rotations of
// such a number differ by the rounding alone. No published definition asks
// for the rounding. `⊤` is NOT in the list: its digits go through the float
// path either way, and the tolerant residue reads a remainder of 3 beside a
// modulus of 2^63 as zero, which is what GNU APL answers too.
9223372036854775806|2 3⍴⍳6
? the exact residues here, the residues of 2^63 there
9223372036854775806⌽¯2 0 2
? the exact rotation here, the rotation by 2^63 there
// A width or a precision is a length, and a written number can ask for more

9223372036854775806⍕1

1 9223372036854775806⍕1

// A scan over an empty keeps the argument's shape, as GNU APL's own `+\`
// and `×⍀` do. Its `-\` and `-⍀` drop the result to a rank-1 empty instead,
// which is the shape bug this release fixed on libjay's side.
⍴-\\0 3⍴1
? the argument's shape here, a rank-1 empty there
⍴-⍀3 0⍴1
? the argument's shape here, a rank-1 empty there
// The n-wise reduction of an EMPTY argument of rank 2 or more. The reduced
// axis is `1+≢-|n|` items long, exactly as it is on a non-empty argument,
// so libjay's answer has the argument's rank. GNU APL drops the axis
// instead — the shape its ORDINARY reduce gives — but only when that length
// is not zero, and not when n is 0: `⍴1+⌿0 3⍴⍳0` is `0 3` and `⍴0+/0 3⍴⍳0`
// is `0 4` there, both with the axis kept. The three cases cannot come from
// one rule, and libjay applies the one rule everywhere.
⍴2+/0 3⍴⍳0
? the reduced axis stays here, an empty argument drops it there
⍴1+/0 3⍴⍳0
? the reduced axis stays here, an empty argument drops it there
⍴2+/2 0 3⍴⍳0
? the reduced axis stays here, an empty argument drops it there
⍴2+/0 3 4⍴⍳0
? the reduced axis stays here, an empty argument drops it there
// The same argument one step further: with no cells to fold there is no
// window to be too long for one. libjay learns the answer's shape from a
// cell of fills, and a fill cell the function refuses leaves a plain empty;
// GNU APL measures n against the axis first and refuses. On a NON-empty
// argument the two agree that an over-long window is a domain error.
⍴2+/0 0⍴⍳0
? an empty answer here, a domain error there

0,/2 3⍴⍳6
